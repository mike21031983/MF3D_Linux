# CP10 — единый диагностический сеанс MF3D, только чтение

Дата: 2026-10-20. Основание: оригинальные Win/Mac Utility, реверс Mach-O и штатного device.mf_3d.js, сохранённые приватно в recovery. Новых неопознанных SysEx-запросов не добавлено.

## Один сеанс

В GUI появилась кнопка «Единое чтение: модель + параметры + RGB», которая последовательно отправляет **только четыре ранее исследованных READ запроса**:

1. F0 00 01 79 05 F7 — определить модель, разрешена только family 0003 / model 0001.
2. F0 00 01 79 02 00 F7 — запрос основных параметров (02 01 ответ).
3. F0 00 01 79 04 01 01 F7 — 192 RGB7 компонента цвета отпущенных кнопок.
4. F0 00 01 79 04 01 02 F7 — 192 RGB7 компонента цвета нажатых кнопок.

Для второй, третьей и четвёртой команд сохраняется идентификационный guard из CP08. Нет EEPROM, persistent WRITE, DFU, reset, firmware update. Запросы отправляются только после явного нажатия кнопки. Если идентификация завершилась неуспешно, другие запросы не посылаются. Тайм-аут 02 01 не становится «успешным завершением»; чтение цветов может продолжиться с отсутствующим набором основных параметров и предупреждением.

**Полнота основных настроек по-прежнему НЕ подтверждена.** Ни дизассемблированный код, ни синтетические тесты не доказывают END-маркер. В JSON всегда main_settings_complete=false; «настройки» отражают только последний принятый ответ, не итоговый профиль для загрузки в память.

LED цвета считаются полными только при 192+192 значениях и подтверждённом по статическому коду признаке завершения. При timeout/invalid ответе частичные данные не выдаются.

## Диагностика

- MF3D_read_audit.json — локальная сводка без серийного номера: модель, наблюдения, цвета, ошибки, статус неполноты.
- MF3D_PRIVATE_MIDI_trace.json — сырые SysEx, только отдельное подтверждение и локальный файл. Может содержать уникальный идентификатор устройства. Не выкладывать на GitHub.
- Трасса совместима с автономным CLI-анализатором CP09. Ограничение в памяти — 256 событий; файлы создаются только новыми (exclusive create), без перезаписи.

## Проверки и ограничения

86/86 локальных unit PASS; compileall PASS; Xvfb + имитация реального GUI-цикла из четырёх запросов PASS. GitHub Actions/runners 0. Физический MIDI Fighter 3D пока не подключался; Windows/Mac equivalence на уровне SysEx и все операции записи не доказаны. Ни одной persistent write или firmware операции.

Следующий этап: устранить несовпадения UI и подготовить один осмысленный реальный тест чтения с контроллером после готовности приложения; до этого не отвлекать пользователя мелкими тестами.
