# CP05 — протокол основных настроек MIDI Fighter 3D (20.10.2026)

## Подтверждённые команды оригинального macOS Utility

Исходные установщики пользователь предоставил отдельно. В публичном репозитории **нет фирменных бинарников**. Анализ выполнялся по Mach-O оригинальной программы; архив recovery содержит исследовательский дизассемблированный фрагмент.

- `Device::requestConfig()`, адрес `0x10010d8d0` в извлечённом Mach-O. Сборка SysEx `F0 00 01 79 02 00 F7`. После формирования проверяется состояние распознанного/открытого устройства (поле `0x109 == 1`). Вызов `Midi::sendTo` использует MIDI command `0x0f`.
- `ConfigWidget::sysEx()`, адрес `0x100104820`: при manufacturer `00 01 79`, payload `02 01` обрабатываются последовательные **пары tag/value** с позиций `payload[2:]`. Значения передаются в `MidiSerializer::write(tag,value)`. Это приём основных настроек.
- `ConfigWidget::requestConfig()`, `0x10010acd0` — другой метод, планирующий обратный вызов интерфейса, **не отправляет запрос**.
- `MidiSerializer::send()`, `0x100101ff0`, вызывается через `ConfigWidget::sendToDevice()`, `0x100104730` — путь **записи**, поэтому не используется в нашей реализации.

Ранее в CP04 восстановлены запросы цветов (блоки 1 и 2): `F0 00 01 79 04 01 TAG F7`.

## Реализация

- `config_read.py` создаёт исключительно подтверждённый запрос **02 00**, без команд записи.
- `midi_backend.py` разрешает отправку только после явного вызова и только в MIDI output с идентифицируемым именем MIDI Fighter. Совпадение имени порта ещё **не доказывает модель или ревизию**.
- `serializer_capture.py` реализует пассивную обработку ответов **02 01**: пары tag/value, сохранение неизвестных тегов, фиксация конфликтующих значений, жёсткие ограничения размера и формата, JSON экспорт с явным статусом `partial_observation_not_verified_full_config`.
- `app.py` — отдельная кнопка чтения, ожидание ответа 4 секунды, безопасный экспорт. Без подключения запрос не отправляется. В контроллер не загружается/не записывается ничего.
- Предыдущие режимы CP04 (RGB7 192+192, профили offline, просмотр .mfs) сохраняются.

## Что НЕ доказано

1. Получен ли весь набор параметров в одном SysEx ответе или в нескольких.
2. Есть ли и как распознать явный завершающий сигнал именно для `02 01`. Поэтому отложенная/частичная выгрузка **не считается полным текущим профилем устройства**.
3. Точное соответствие байтов отдельных параметров UI-единицам, особенно процентов и составных bitflags, требует эталонного сравнения. Имена тегов из оригинального JS используются только как аннотации, без автоматического применения значений.
4. Протокол не проверялся на физическом MIDI Fighter 3D. Только синтетические unit-тесты и Xvfb.
