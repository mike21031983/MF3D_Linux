# MF3D Linux — нативный MIDI Fighter 3D Utility

**Цель:** полная функциональная замена фирменного MIDI Fighter Utility под Linux Mint, без Wine и Windows API.

**Статус CP04 (20.10.2026): прототип, не готовая 1:1 замена.** Уже написаны Linux GUI, MIDI-матрица 4×16, ALSA/RtMidi backend, MIDI-монитор и управление LED цветом/анимациями на основе официального руководства. Пока **не проверено на реальном MIDI Fighter 3D**. Запись постоянных настроек устройства, полный GUI фирменной утилиты и прошивка пока не реализованы.

## Запуск на Linux Mint 21.3

```bash
sudo apt install python3-tk python3-mido python3-rtmidi
python3 -m mf3d_linux
```

Запуск не требует root, драйвера ядра или Wine. Контроллер использует стандартный USB-MIDI, утилита подключается к MIDI IN/OUT через ALSA.

## Статические тесты (не Actions)

```bash
python3 -m unittest discover -s tests -v
python3 -m compileall -q mf3d_linux
```

## Обратный инжиниринг оригиналов

Пользователь предоставил оригинальные `Midi_Fighter_Utility_OSX.dmg` и `Midi+Fighter+Utility+Win.exe`. macOS DMG разобран до HFS+ и Mach-O; обнаружены Qt, RtMidi, и символы `MidiSerializer::send/read/write`, `ConfigWidget::pushBulkTransfer/pullBulkTransfer`, `Midi::sysEx`. Windows EXE определён как Inno Setup/PE32, извлечение payload ещё не выполнено. Файлы прошивки 3D из DMG не использовались.

Пока полная документация команд persistent SysEx не проверена, в новом Linux коде **нет операций прошивки, factory reset и записи EEPROM**: риск испортить устройство недопустим. MIDI Live LED protocol документирован в руководстве DJ TechTools v1.03.

Исследовательская хронология, оригиналы и инструменты извлечения лежат в частном **recovery ZIP**, не в открытом GitHub. Не публикуйте чужие бинарники и `.hex` в репозитории.

Этот независимый проект не связан с DJ TechTools.


## CP02 — Реверс штатного модуля MF3D (20.10.2026)

В оригинальном DMG найден `Contents/Resources/plugins/device.mf_3d.js` (49 885 байт). Для семейства `0003`, модели `0001` оттуда восстановлены все 17 настроек и теги: MIDI Channel 0, MIDI Velocity 1, Bank Buttons 3, Software Mode 7, Combos 8, анимации 10 (несколько полей с общим тегом), Rotation 11, Tilt Directions 12, Tilt Sensitivity 14, Tilt Range 16, Rotation Range 17, Tilt Dead Zone 18, Join CCs 20, Pickup Sensitivity 21, Sleep Timer 22, Bank Side Buttons 23.

Штатные цвета: 4 банка × 16 кнопок × RGB, `tag=1` — inactive, `tag=2` — active, 192 RGB7 компонента на каждый буфер (8-битный канал / 2). 20 цветов штатной палитры в `device_profile.py`. Добавлен нативный **локальный редактор профиля** в `profile_editor.py`: Settings / Motion / Colors, выбор банков, Off/On colors, экспорт и импорт JSON. Заданы проверки диапазонов, сохранение неопределённых битов тега анимаций.

В Mach-O дизассемблированы `ConfigWidget::sysEx`, `pushBulkTransfer`, `pullBulkTransfer`: по фрагментам подтверждены идентификатор `00 01 79` и семейства пакетов `02 01`, `04 00` и исходящий запрос `04 01`. Реализован только **пассивный** анализ в `vendor_sysex.py` (без отправки SysEx). Сообщения от устройства не зафиксированы: анализ основан на оригинальном коде, а не на реальном USB-трафике.

**Ограничения:** EEPROM/flash/DFU, чтение и запись настроек устройства ещё не реализованы; импорт экспортом в штатный `.mfs` пока тоже не обеспечен (в JSON используется наш формат). Собственный редактор **не** обещает совпадения с реальными состояниями контроллера, пока не реализована загрузка их с устройства. Оригинальные установщики, прошивки и штатный JS хранятся только в приватном recovery, но не публикуются в GitHub.

**Проверки:** локальные Python-unit и headless GUI через Xvfb. GitHub Actions/runners не запускались (0 раз).


## CP03 — Windows и Mac теперь сравниваются напрямую

Установщик Windows Inno Setup разобран без Wine. Найден корректно распаковываемый LZMA1 solid stream **90,062,033 байта**, в нём — основной Qt6/RtMidi x64 EXE и библиотеки. Из этого потока извлечён `device.mf_3d.js`, совпадающий побайтно с тем же файлом из macOS DMG: SHA-256 `81ad526846050fefc698f64e6e9570996d2c89f9ca9946ba0a93f0ec4cc98875`. Код распаковки: `research/extract_inno_lzma.py`, код сравнения: `research/compare_3d_plugins.py`. Фирменные бинарники в репозиторий не добавляются.

На основании дизассемблирования оригинальных `buildMfsBlob` и `importSettingsFromBlob` написан **только читающий** инспектор бинарных `.mfs` с проверкой 2-байтной длины сериализатора и повторяющихся блоков tag/type/length/data. Нативный GUI умеет открыть файл для анализа, но не загружает его в контроллер. Необходима проверка настоящего экспортированного `.mfs`.

Локальные тесты **19 PASS**, GitHub Actions и runners **0 запусков**, USB-девайс не тестировался, EEPROM/SysEx write/DFU/flash не выполнялись. Полный отчёт: `docs/CP03_WINDOWS_AND_MFS_RU.md`. Состояние **не равно** готовой замене официального Utility.

## CP04 — ограниченное чтение цветовых блоков по SysEx

Из оригинального macOS Mach-O получен точный read-only запрос `F0 00 01 79 04 01 TAG F7` для тегов 1 и 2; они содержат цвета 64 кнопок (192 RGB7 значения каждый). На входе ожидается фирменный ответ `04 00` с фрагментами. Добавлены `bulk_read.py` и `color_read_session.py`, включая длины, тайм-аут, двухступенчатую загрузку, отказ от неполных данных.

В Linux GUI появилась кнопка **«Считать цвета с MF3D»** — лишь по явному нажатию, никаких автозапросов. `send_color_read_request` отказывает в работе с неидентифицированным MIDI-портом и не содержит отправки write/reset/DFU. Отдельный JSON экспорт содержит **только считанные цвета**, а не все настройки.

**Контроллер пока не проверялся физически; чтение экспериментальное.** Новые тесты используют полностью искусственные входные сообщения. Дополнительная документация — `docs/CP04_READONLY_SYSEX_RU.md`. GitHub Actions/runners не запускались (0).
